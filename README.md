# Rastboden (school deposit tool)

A small app for school staff to keep track of which toy is lent to which child,
and for how long. It is a PWA: it is installed from the browser on iOS and
Android, works offline, and keeps all data on the device. Nothing is sent
anywhere; the only way data leaves is a backup file that staff save themselves.

## Commands

```
npm install        # once
npm run dev        # start the dev server
npm run typecheck
npm run lint
npm test
npm run build      # production build in dist/
npm run preview    # serve the production build (the service worker only runs here)
```

## Stack

| Concern    | Choice                                             |
| ---------- | -------------------------------------------------- |
| App        | Vite, React, TypeScript                            |
| PWA        | `vite-plugin-pwa` (manifest + offline cache)       |
| Storage    | IndexedDB through Dexie                            |
| Forms      | react-hook-form + zod                              |
| UI         | Tailwind CSS + shadcn/ui components                |
| Languages  | i18next, Swedish (default) and English             |

## Layout

```
src/
  db/          tables and the functions that read and write them
  features/    one folder per screen (loans, toys, children, statistics, settings)
  components/  shared layout pieces; ui/ holds generated shadcn components
  i18n/        setup and the sv / en texts
  lib/         small helpers (image resizing)
```

## Things worth knowing

- **Loans are history.** Returning a toy sets `returnedAt`; the row stays. Toys
  and children are archived, not deleted, for the same reason. Statistics will
  are built from this history.
- **A toy is one physical item** and can only be out on one loan at a time.
- **Loan times** to choose from are set in `DURATION_CHOICES` in
  `src/features/loans/LendDialog.tsx`.
- **Statistics** are computed in `src/features/statistics/statistics.ts` from the
  loans in the chosen period. The charts are plain HTML and CSS, with no chart
  library; the bar colour is `--chart-1` in `src/index.css`.
- **Toy images** are shrunk to at most 512 px (JPEG) before they are stored, and
  live in their own table so that listing toys never loads image data.
- **Texts** go in `src/i18n/locales/sv.ts` first; `en.ts` must have the same
  keys, and a missing or misspelt key is a compile error.
- **Routing uses the URL hash** and the build uses relative paths, so `dist/`
  can be hosted from any sub-path (for example GitHub Pages) as it is.
- **App icons** are all generated by `npm run icons`
  (`scripts/generate-icons.mjs`), which holds the artwork. Change the icon
  there, not in `public/`: iOS and Android crop icons differently, so the
  script draws a separate version for each.

## Hosting

The app is published with GitHub Pages by `.github/workflows/deploy.yml`: every
push to `main` runs lint, tests and the build, then publishes `dist/`. In the
repository settings, Pages must have **Source: GitHub Actions**.

The address is where each device keeps its data. If the address changes
(another account, repository name or host), devices start empty at the new
one, so settle the address before the app is in use.

## Keeping the data safe

All data lives in the browser on one device, so three things guard it:

- **Persistent storage.** At start the app asks the browser not to clear its
  data on its own (`src/lib/persistentStorage.ts`). Settings shows the answer.
  Browsers mostly say yes once the app is on the home screen.
- **Backups.** Settings can save everything to one JSON file and read it back
  (`src/db/backup.ts`). Restoring replaces everything on the device, all or
  nothing. A dot on Settings reminds staff when there is data and no backup
  from the last 7 days (`BACKUP_REMINDER_DAYS`). This is the only protection
  against a lost device or a removed app.
- **Schema changes.** `src/db/upgrade.test.ts` opens a database laid out by
  each earlier version and checks that nothing is lost. When `schema.ts` gets
  a new version: add a block there, raise `BACKUP_VERSION`, and keep
  `parseBackup` able to read the older backup files.
